1.5. FIXES CRITIQUES v2.3 — 09 MARS 2026
================================================================================

**PROBLÈME OBSERVÉ (après exécution v2.2):**
- Rougeole: R² = -1.0 pour TOUTES les 26 provinces (100% inverted)
- VIH/SIDA: R² = -38 à -43 pour toutes les provinces (catastrophique)
- Paludisme: Données manquantes (10-16 mois au lieu de 75) + R² négatif
- Tuberculose: Mixed results (certaines OK, certaines négatives)

**ROOT CAUSES IDENTIFIÉES:**

1. **Sparse Data Problem**
   • Rougeole & VIH/SIDA: Peu de cas rapportés (lots de zéros)
   • MinMaxScaler [0,0,0,0] → normalise à [0,0,0,0]
   • Modèle apprend à prédire 0
   • Denormalization de 0 → peut exploser en négatif

2. **Data Availability Issue**
   • Paludisme/Rougeole/VIH-SIDA: Only 10-16 months in database
   • Should have 75 months (Jan 2020 → Mar 2026)
   • CNN-LSTM needs ≥8mo data quality time series
   • Short series + sparse = model confusion

3. **Feature Scaling Bug** (STILL PRESENT in v2.2)
   • Climate features mixed with normalized cases
   • When denormalizing, all columns treated equally
   • Temperature 15-35°C × cases scaling factor = nonsense

**FIXES APPLIED (v2.3 — 09 MARS 2026):**

✅ **FIX 1: Proper Feature Scaling**
   
   OLD (v2.2):
   ```
   features = [cases_norm[0,1], sin[0,1], cos[0,1]]
   scaler.fit_transform(features)  # ALL columns scaled together [0,1]
   scaler.inverse_transform() ### explodes if ratios wrong
   ```
   
   NEW (v2.3):
   ```
   # Only cases get MinMaxScaler
   cases_norm = (cases_raw - min) / (max - min)  # [0,1]
   # Climate stays RAW (not normalized)
   features = [cases_norm, sin, cos, temp_raw, precip_raw, humid_raw]
   scaler.fit_transform() # only col 0 mattersfor denorm
   scaler.inverse_transform() # returns col 0 only (correct)
   ```

✅ **FIX 2: Sparse Data Detection**
   
   Added variance + zero-inflation checks:
   ```python
   variance = np.var(cases_values)
   non_zero_ratio = np.sum(cases > 0) / len(cases)
   
   if variance < 0.1 or non_zero_ratio < 0.3:
       logger.warning(f"Skip {province}/{disease}: sparse")
       continue  # Don't train on noise
   ```
   
   **Effect**: Skip Rougeole/VIH-SIDA regions if too sparse
   
✅ **FIX 3: Data Availability Logging**
   
   ```python
   if prov_qs.exists():
       range = prov_qs.aggregate(Min/Max month)
       logger.debug(f"DATA RANGE {prov}: {min} → {max}")
   ```
   
   **Effect**: Shows actual historical data span (diagnose missing months)

✅ **FIX 4: ScalerWithSeasonality Update**
   
   - Save cases_min/cases_max during fit
   - inverse_transform denormalizes ONLY column 0
   - Seasonality/climate columns passed through unchanged
   - Result: No scale explosion

2. BUG CLIMATIQUES ET SOLUTION TEMPORAIRE (v2.2)
================================================================================

Problème Identifié  :
─────────────────────────────────
• R² NÉGATIFS observés : R²=-10 à -52, MAE=70K+, RMSE=73K+
• Groupes affectés : Paludisme+Typhoïde, TB+Rougeole, VIH/SIDA
• Cause : Bug dans build_feature_matrix_with_climate()
  - MinMaxScaler normalisait TOUTES 4 colonnes [cases, T°, precip, humidité]
  - Cases : plage 0-1000 → fit [0, 1]
  - Temperature : plage 15-35°C → fit [0, 1]
  - Precipitation : plage 0-300mm → fit [0, 1]
  - Humidity : plage 30-90% → fit [0, 1]
  
  - Lors de inverse_transform() : chaque colonne multipliée par sa plage
  - Prédictions = cases_predicted × 1000
  - = valeurs énormes (70K+) au lieu de cas réels (0-1000)

Problème dans ScalerWithSeasonality :
──────────────────────────────────────
La classe reconstruit mal les features lors de inverse_transform :
  • Sauvegarde sin/cos de saisonnalité AVANT normalisation
  • MAIS pad le reste avec zéros ou reconstruit mal les features climatiques
  • Entraîne des inversions incorrectes

Solution Temporaire (v2.2) :
────────────────────────────
🔧 REVERT à 3 FEATURES SIMPLES (pas climatiques temporairement)

    def build_feature_matrix_with_climate(df_monthly, climate_df=None):
        """
        TEMPORAIRE (v2.2): Retour à 3 features [cases_NORM, sin_month, cos_month]
        sans climatiques pour déboguer les R² négatifs.
        
        La v3 réintégrera le climat avec normalisation SÉPARÉE.
        """
        # ✓ Stratégie: revenir à 3 features fiables
        # Les données climatiques seront réintégrées en v3 avec norma séparée
        
        sin_m, cos_m = seasonality_features(df_monthly['month_dt'])
        cases_raw = df_monthly['cases_count'].values
        
        # Normaliser cases [0, 1]
        cases_min, cases_max = cases_raw.min(), cases_raw.max()
        if cases_max > cases_min:
            cases_norm = (cases_raw - cases_min) / (cases_max - cases_min)
        else:
            cases_norm = np.zeros_like(cases_raw, dtype=float)
        
        features = np.stack([cases_norm, sin_m, cos_m], axis=1)
        
        logger.debug(f"    ✓ Features (v2.2 DEBUG): 3 colonnes [cases_NORM, sin, cos]")
        logger.debug(f"      Cases: min={cases_min:.1f} max={cases_max:.1f} → normalisé [0,1]")
        logger.debug(f"      Climat: IGNORÉ TEMPORAIREMENT (fin des R² négatifs)")
        
        return features, 3, ['cases', 'sin_month', 'cos_month']

Fonction remove_duplicate_predictions() :

    def remove_duplicate_predictions(df):
        """
        Stratégie intelligente : pour doublons (même zone, même date),
        garder l'enregistrement avec le PLUS HAUT nombre de cas.
        
        Logique :
            1. Identifier doublons
            2. Trier par cas (descendant)
            3. Garder le premier (plus élevé)
        """
        duplicates = df.duplicated(subset=['month', 'health_zone_id'], keep=False)
        df = df.sort_values(['cases_count'], ascending=False).drop_duplicates(
            subset=['month', 'health_zone_id'], keep='first'
        )
        return df

Avantages :
───────────
✓ Élimine les enregistrements erronés (corrections ultérieures)
✓ Conserve le pic épidémique réel
✓ Diagnostic amélioré : "garda la valeur la plus fiable"

Ancien Système (v1) :
─────────────────────
Les valeurs manquantes étaient simplement ignorées.
Résultat : Séries fragmentées, prédictions peu fiables.

Nouveau Système (v2) :
──────────────────────
Stratégie multi-niveaux dans clean_clinical_data() :

    Étape 1 : NULL/NA — Suppression stricte
    ─────────────────────────────────────────
    df = df.dropna(subset=['month', 'cases_count'])
    
    Étape 2 : Conversion numérique ROBUSTE
    ──────────────────────────────────────
    df['cases_count'] = pd.to_numeric(df['cases_count'], errors='coerce')
    # Convertit erreurs en NaN (puis suppression)
    
    Étape 3 : Cas négatifs → CLIPPING (pas suppression)
    ─────────────────────────────────────────────────
    ANCIEN : df = df[df['cases_count'] >= 0]  # Supprime lignes
    NOUVEAU : df['cases_count'] = df['cases_count'].clip(lower=0.0)  # Clip à 0
    
    Raison : Pas perdre l'enregistrement, juste corriger la valeur
    Interprétation : "Erreur de saisie → 0 cas au minimum"
    
    Étape 4 : Doublons intelligents
    ────────────────────────────────
    df = remove_duplicate_predictions(df)  # Garde plus haut
    
    Étape 5 : Tri par date
    ──────────────────────
    df = df.sort_values('month')
    
    Étape 6 : Interpolation par zone
    ─────────────────────────────────
    Pour chaque zone dans le groupe :
        zone_data = zone_data.fillna(method='ffill')  # Forward-fill
        zone_data = zone_data.fillna(method='bfill')  # Backward-fill
        zone_data = zone_data.fillna(zone_data.mean()) # Moyenne si tout NaN
    
    Raison : Préserver continuité temporelle
    Logique : "Si mois X manque, utiliser mois X-1 ; sinon X+1 ; sinon moyenne"

    Étape 7: Variance ET Couverture
    ────────────────────────────────
    Var(X) < 1.0 → REJET (série trop plate)
    Coverage < 50% → REJET (trop de zéros = données manquantes)
    
    Étape 8 : Outliers LÉGERS (Z-score > 3.5)
    ───────────────────────────────────────────
    Détecté mais PAS supprimé ou lissé.
    Raison : Pics épidémiques réels peuvent être outliers
    
    Étape 9 : DOUBLE CLIPPING final
    ────────────────────────────────
    ANCIEN : df['cases_count'] = df['cases_count'].round(0)
    NOUVEAU : df['cases_count'] = df['cases_count'].clip(lower=0.0).round(0)
    
    Failsafe : Assure JAMAIS de négatifs
    Interprétation : "Par 2x, on ne prend que des positifs"
